# 新方向立项立论与 Go/No-Go 决策报告 (One-Page Decision)

> **决策基准**：本报告综合 Stages 1–11 历史证据总账、相关文献核验（含 ACL 2024 Agent-Pro、Safe RL Shielding、Constrained Tool Decoding）、全套 9 项 CPU 验收测试以及冻结协议下的 36 次模型受控运行（V2.0 真正多步部署运维环境）。预算用完即停止，不扩大实验。

## 一、核心决策三问明确回答

### 1. 相比动态事实记忆 (B2)，候选方法 (Method M) 究竟多做了什么？
- **动态事实记忆 (B2)**：记录环境客观状态命题（World Facts）。B2 将观测到的事实直接放入 Prompt 上下文，依赖大模型自身的自回归推理去自发规避冲突。
- **候选条件化失败约束记忆 (M)**：在 B2 基础上显式增加了独立的确定性生命周期状态机：
  1. **规则有效性 (Validity)** 与 **当前适用性 (Applicability)** 解耦；
  2. **候选试探机制 (CANDIDATE Probationary Trial)**：单次提取的规则默认处于候选期，允许有限试探执行，不直接硬阻断；仅在复现后升级为 `SUPPORTED`；
  3. **通用谓词门禁与主动探测 (Generic Predicate Gating & Probing)**：在动作提议后、实际执行前评估前置条件，当条件为 `UNKNOWN` 时触发针对性探测；当动作在适用条件下成功执行时将规则标记为 `CONTRADICTED`。

### 2. 这个差异为何可能带来可测收益？
1. **防止模型概率采样带来的重复盲目尝试**：通过执行前门禁确定性拦截已知必败动作；
2. **避免过时反思的守旧死锁**：当条件解除变为 `NOT_APPLICABLE` 时释放动作，避免传统纯文本反思的不可逆负向偏置；
3. **防止候选假设过度阻断**：候选规则放行机制保护可行动作不被初次单点偶发报错扼杀。

### 3. 区分有效机制与重新包装的关键评估边界
为避免在探索偏置下脱离因果检验而武断下结论，需在严格控制变量与真实因果介入下评估：
1. **在冲突前提实际发生时是否具备确定性防护**：当 Agent 提议被前置条件禁用的动作时，门禁能否有效实施精准拦截（TP 拦截）并防止重复失败，而非依赖模型自回归的不可靠猜测；
2. **在动态条件解除时是否避免死锁**：当约束条件变化解除时，机制能否及时恢复放行，而非造成永久性负向偏置或高误阻断（FP 误拦截）；
3. **成本与收益权衡**：状态维护、主动探测及生命周期转化的开销与减少的执行故障风险相比是否在合理工程边界内。

## 三、细粒度机制归因与审计说明

1. **探索优先策略使模型天然实现零执行错误**：
   - 在真实的无作弊多步任务中，`Qwen3-14B-AWQ` 在温度 0.0 下自发采取了“先探后动”的严谨探索策略：
     `discover_environment` $\to$ `probe_port` $\to$ `probe_directory` $\to$ 确认可用才调用 `write_config` 与 `start_service`。
   - 该自适应规划策略导致无记忆基线 B0 在全部 8 个目标实例上均自发避开了占用端口与只读目录，**提议错误动作数为 0，实际执行错误为 0**。
2. **门禁机制缺少真实触发机会**：
   - 因为模型未直接盲目发起冲突操作，门禁（B2-G 与 M）在整个测试集中**触发机会为 0**（TP=0, FP=0）。
   - 依据科研诚信准则：在没有实际触发机会的情况下，**绝不能将 100% 成功率归功于门禁有效性**。
3. **源任务未产生自然失败，目标评测处于空记忆条件**：
   - 在两组源任务中，B0 同样通过前置探测成功完成了部署，未产生实际执行错误；依据证据链规范，未强行伪造失败记录，记忆模块保持空状态（`target_initial_memory_count = 0`）进入目标任务。
   - **记忆审计指标核验表**：
     | 审计指标 | 实测值 | 审计含义 |
     | :--- | :---: | :--- |
     | `source_failure_count` | 0 | 源任务真实失败记录数 |
     | `extracted_rule_count` | 0 | 确定性提取规则数 |
     | `target_initial_memory_count` | 0 | 注入目标评测的初始非空记忆数 |
     | `matched_rule_count` | 0 | 目标动作匹配规则数 |
     | `gate_opportunities` | 0 | 门禁评估机会总数 |
     | `lifecycle_transition_count` | 0 | 状态机生命周期流转数 |
   - **关键审计结论**：实验处理（Treatment）未实际生效，记忆模块为空，四组实际上均在无跨任务经验的状态下运行，因此**不能评价记忆的独立贡献**。
4. **成本开销对比**：
   - 四组调用步数均为 7.50 步，B0、B2、B2-G、M 的 Token 与耗时差异小于 1%，四者表现完全等价。

## 四、最终 Go/No-Go 结项决策决议

### 决策结论：【生产执行路径全线贯通；大模型探索偏置下门禁未受压测】

根据实测数据与代码实现，对系统效能进行三层清晰定性：

1. **第一层：单元测试与确定性状态机闭环（已验证）**
   - 约束生命周期状态机（`CANDIDATE` $\to$ `SUPPORTED` $\to$ `CONTRADICTED` $\to$ `RETIRED`）逻辑经 46 项 CPU 单元与集成测试全量验证（100% Pass）。
   - 前置条件动态适用性评估（`APPLICABLE` / `NOT_APPLICABLE` / `UNKNOWN`）、证据去重与幽灵增益防范、前置快照防观测漂移等机制，在纯逻辑层面完全自洽闭环。

2. **第二层：真实环境生产执行路径贯通（已通过真实环境 CPU 集成测试）**
   - 在真实操作系统 Socket、真实非 root 用户权限和独立 Verifier 下，通过 production runner 实现全流程贯通（`results/runner_integration_events.json`）：
     - **路径 A**：真实 OS 失败提取 $\to$ `CANDIDATE` 生成 $\to$ 试探执行复现 $\to$ `SUPPORTED` 升级 $\to$ 后续硬拦截成功；
     - **路径 B**：前提解除 $\to$ 门禁放行 $\to$ 动作成功在空闲前提下因果不矛盾 $\to$ 前提恢复重新拦截；
     - **路径 C**：缺失/过期观测 $\to$ 门禁自动探测 $\to$ 真实 `call_id` 观测入库 $\to$ 消除死循环；
     - **实验隔离与顺序不变性**：源记忆快照 SHA256 冻结；B0/B2/B2-G/M 及其逆序执行时，各组初始记忆 Hash 与证据列表恒等，无跨任务及组间观测污染。

3. **第三层：大模型真实运行观察（受控模型冒烟与实测归因）**
   - **描述性事实**：在大模型受控运行中（V2 全量 32 目标运行与 V3 受控冒烟运行），Agent 自发采取了“先探后动”的高谨慎度探索策略（`discover_environment` $\to$ `probe_port` $\to$ `probe_directory` $\to$ `write_config`），在当前环境中天然避开了冲突动作。
   - **科学定性**：不能将模型因探索偏置未触发门禁误判为“机制冗余”或“方法无效”；同样，在门禁未发生真实拦截的情况下，也不能将高成功率夸大为“门禁赋能”。当前实测定性为：在当前探索偏置环境下，大模型未发起冲突提议导致门禁缺乏自然受压机会；机制本身的因果拦截力已在真实生产执行路径中通过自动化集成测试证实。

4. **结项建议**：
   - 生产执行代码、CPU 闭环集成测试套件（46/46 Pass）、V3.0 冻结协议全部交付；
   - 严格遵守计算预算，冻结大规模目标实验；后续若需检验门禁的大模型端增益，必须设计具备信息隐蔽性、对抗性突发冲突或必须依赖历史经验的前置不可探查故障场景。
