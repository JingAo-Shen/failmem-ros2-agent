# FailMem：最小研究契约与问题锁定 (Problem Lock)

- **协议状态**: **P0 冻结 (Locked for P1 Implementation)**
- **版本**: 1.0 (2026-09-26)
- **适用范围**: failmem-ros2-agent P1 最小物理闭环至 P3 正式实验规范

---

## 1. 任务定义与边界
- **场景限定**: 单个 ROS2 移动机器人（基准形态：TurtleBot3 Waffle 差速底盘），室内仿真环境。
- **任务目标**: 给定初始目标语义与粗略坐标，机器人自主规划导航到达目标区域，并在目标前执行传感器观察，确认目标存在与可见性。
- **排除范围**: 暂不涉及机械臂抓取、多机器人协作、在线强化学习、端到端视觉大模型微调、Web 控制平台和实物真机部署。

---

## 2. 机器人动作空间与协议契约

机器人仅允许通过受控的高层类型化动作接口与仿真环境交互，所有动作具有明确的前置检查、超时阈值与预算约束：

| 动作名称 | 输入参数 | 正常返回与状态 | 超时/限制 | 底层对应与消耗 |
| :--- | :--- | :--- | :--- | :--- |
| `navigate` | `{"goal": [x, y, yaw]}` | `SUCCESS` (到达目标附近并停稳) / `FAILED` (超时或路径阻挡) | 仿真时间 60s 动作超时 | 对应 Nav2 `NavigateToPose` Action。消耗 1 次动作预算与实际物理移动耗时。 |
| `observe` | `{"target_id": str}` | `VISIBLE` (目标在视野内且无遮挡) / `NOT_VISIBLE` (目标不在视野或被遮挡) | 仿真时间 5s | 触发前向相机/深度传感器射线检测，返回检测置信度与时间戳。消耗 1 次动作预算。 |
| `inspect_status` | `{}` | 返回机器人当前位姿估计、激光雷达测距摘要、局部代价地图状态、最近导航动作返回码 | 即时返回 (<0.5s) | 读取 ROS2 `/odom` 与 `/scan`。消耗 1 次动作预算。 |
| `clear_costmap` | `{}` | `CLEARED` (局部代价地图瞬态层清空成功) | 仿真时间 2s | 触发 Nav2 `clear_costmap_service`。**仅重置局部代价地图传感器残留，绝对不能使物理实体障碍消失**。 |
| `retry` | `{"previous_action": str}` | 重新发起上一无效动作并记录尝试 | 继承原动作超时 | 记录重试计数；同一状态同动作最多重试 1 次。 |

- **统一预算上限 (待 P1 实测微调后冻结)**:
  - 仿真总时间: $\le 180\text{s}$ (仿真物理时钟)；
  - 高层动作步数: $\le 20$ 步；
  - 恢复动作调用: $\le 3$ 次；
  - Wall-clock 超时守护器: 真实时间 300s 强制中断，避免推理死锁。

## 3. 公共 Verifier 与独立 Evaluator 隔离机制

必须严格区分 Agent 可见的公共后置条件验证器（Verifier）与最终独立的真值评测器（Evaluator）：

```
[Agent Context]
       │
       ▼ (Action Proposal: navigate / clear_costmap)
[ROS2 Environment / Nav2] ───> Sensors (/scan, /camera, /odom)
       │                              │
       ▼ (Execution Done)             ▼
[Public Verifier (可选开关)] ───> 检查局部传感器后置条件 (雷达前方净空? 位姿误差<阈值?)
       │                           └──> 生成可见反馈 (Verified / Failed)
       ▼
[Independent Ground-Truth Evaluator (严格隔离通道)]
       ├──> 读取 Gazebo 真实全局物理位姿 (Ground-Truth Robot Pose & Target Pose)
       ├──> 到达判定: Euclidean Distance < 0.3m 且静止维持稳定 >= 2.0s
       ├──> 观察判定: Target 确实在相机真值视锥内且 Line-of-Sight 无物理遮挡
       └──> 最终打分: 决定 Episode 最终 SUCCESS / FAILED (模型声明成功无效)
```

- **信息单向流动防泄漏**:
  - Public Verifier 仅读取机器人自身传感器 Topic；
  - Independent Evaluator 读取 Gazebo 模型状态服务（`/gazebo/model_states`）；
  - Evaluator 真值通道与故障注入标签（Ground-Truth Fault Tag）严禁反向流入 Agent 上下文或记忆库。

## 4. 目标观察与感知真值隔离契约
- **视锥与遮挡模型**: 目标观察必须具有物理约束：
  - 水平视角（FOV）: 90 度；
  - 有效视距: 0.5m 至 3.5m；
  - 遮挡判定: 从相机原点到目标包围盒做物理射线碰撞检测，若被墙壁或障碍阻挡，返回 `NOT_VISIBLE`。
- **禁止全知泄漏**:
  - 当目标发生移动时，环境只改变目标实体的物理坐标；
  - **严禁直接把最新真值目标坐标写入 Agent 上下文或 `navigate` 默认参数**；
  - Agent 必须在原目标丢失后，通过主动探索动作或在巡航中通过 `observe` 重新探测到目标，方可获得新目标坐标。

## 5. 三类故障的注入、持续与解除规范

| 故障类型 | 注入机制 | 物理表现与状态持续性 | 有效恢复动作 | 无效/错误恢复后果 |
| :--- | :--- | :--- | :--- | :--- |
| **路径阻塞 (Path Blocked)** | 在路径狭窄关键点生成障碍实体或膨胀虚拟阻挡层 | 实体障碍生成后**持续存在**，直至恢复动作完成；盲目导航必定再次碰撞或被阻挡 | 1. 虚假传感器噪点: `clear_costmap` 生效；<br>2. 实体障碍: 必须 `navigate` 绕行重新规划路径 | 盲重试直接碰撞导致失败；对实体障碍调用 `clear_costmap` 无法解除，仍无法通行 |
| **目标移动 (Target Moved)** | 任务中途将目标位置移动至室内另一合法候选点 | 原目标位置为空，目标位姿改变；机器人到达原点后 `observe` 返回 `NOT_VISIBLE` | 执行主动局部探索/搜索，在视野重新捕捉后更新目标坐标继续导航 | 盲目原地再次 `observe` 持续失败；未观察直接向新目标盲航被系统判定非法作弊 |
| **导航超时 (Action Timeout)** | 人为引发局部代价地图虚假障碍或高频震荡陷入局部死区 | 机器人在容差范围内原地踏步超过 30s，Nav2 返回 `ACTION_TIMEOUT` | 1. 检查状态并清图重置局部代价地图；<br>2. 倒退脱困（Back-up）并重试 | 盲目发起相同长程导航仍落入死区超时；单纯重复重试消耗动作预算至耗尽 |

## 6. 地图版本与失效管理契约
- **三种独立版本号规范**:
  1. `static_map_version` (整数): 静态建筑墙体、房间几何结构的重构版本。任何静态地图变更，所有历史位置坐标强相关经验**全量失效**；
  2. `costmap_update_epoch` (单调递增时间戳/序号): 动态障碍、瞬态感知图层的更新序号。`clear_costmap` 后该版本号递增，依赖该批次障碍的瞬态恢复经验**局部失效**；
  3. `target_observation_epoch` (时间戳): 目标最后一次被真实 `observe` 确认的时间戳。当环境发生目标移动事件后，旧观测戳过期，强制要求重新探测。
- **失效规则检查**:
  - 检索记忆时，必须校验：`current_static_map_version == mem.map_version`，且 `mem.preconditions` 得到当前传感器状态确认；
  - 依赖已改变条件的旧记忆在检索时必须被安全过滤，不得向 Agent 推荐过期动作。

---

## 7. Nav2 恢复行为约束与时钟契约
- **内置恢复行为固定**: Nav2 默认的内置行为（Spin, Back-up, Clear Costmap）必须在全基线中进行固定配置（例如统一关闭自动盲重试，由高层 Agent 显式决策与计数），确保恢复次数计费严格公平。
- **仿真时间 (Sim Time) vs 真实时间 (Real Time)**:
  - 物理世界评测与超时采用 ROS2 仿真时钟（`/clock`，`use_sim_time:=true`）；
  - 当 LLM 规划器进行耗时思考推理时，物理仿真处于暂停（Pause）或世界时钟冻结状态，避免由于大模型网络延迟或本地推理波动破坏物理评测的一致性；
  - LLM 推理延迟、Tokens 消耗由独立 Profiler 记录，计入计算成本表。

## 8. 地图划分与环境资产契约

统一解决历史文档中开发地图数量的冲突，正式确立以下隔离划分标准：

```
[环境资产库: 8 个独立几何拓扑场景]
   ├── 训练集 (Train Set): 3 个场景 (Layout_T1, Layout_T2, Layout_T3) ──> 用于收集训练失败恢复经验
   ├── 开发集 (Dev Set): 2 个场景 (Layout_D1, Layout_D2) ────────────> 用于 P2 机制探索与参数校准
   └── 冻结测试集 (Test Set): 3 个未见场景 (Layout_E1, Layout_E2, Layout_E3) ──> 仅在 P3 正式测试开启
```
- **开发与测试严格隔离**: 任何用于开发调试、消融分析的场景及其近重复几何结构，**绝对禁止**流转进入正式测试集。
- **P1 启动前提**: P1 阶段仅需准备 1 个真实的物理仿真环境（如基于 TurtleBot3 World 或 AWS Small Warehouse 的标准闭环），完成环境接口冒烟与事件重放验证，无需预先构建全部正式测试地图。

## 9. 评测情境与控制集设计
为保证科学评估的因果性，评测场景库必须包含四类对照样本：
1. **无故障控制样本 (No-Fault Control)**: 与故障样本配对，检验恢复与记忆机制是否会损害正常任务的效率与成功率；
2. **相似症状不同恢复样本 (Same Symptom, Distinct Recovery)**: 同为 `Path blocked`，一类为瞬态雷达噪点（清图即可恢复），一类为实体障碍（必须绕行规划），检验记忆是否包含充分适用前置条件；
3. **旧记忆陷阱样本 (Stale Memory Trap)**: 在地图版本或障碍物状态变更后，测试 Agent 是否会盲目套用旧经验；
4. **不可恢复绝境样本 (Unrecoverable Traps)**: 彻底封死目标，检验 Agent 能否及时中止任务宣告无法达成，避免反复无限无效重试。
