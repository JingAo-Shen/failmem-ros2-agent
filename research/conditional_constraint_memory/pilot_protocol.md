# 候选机制最小概念验证协议 (PoC Pilot Protocol)

> **方案性质与执行规范**：
> 1. 本协议为“条件化失败约束记忆”的**探索性概念验证（PoC）设计方案，本轮不运行模型实验（新增 GPU 预算严格为 0）**；
> 2. 评测总运行次数**严格限制在 40 次以内**；
> 3. 明确来源任务、目标任务、状态变更条件与样本单位；
> 4. **科研规范**：严禁使用“8 个任务未达显著性即彻底证伪”的伪统计学规则；将决策严格解耦为四级归因；区分工程决策准出线与普遍科学结论；审慎测算硬件运行时间。

---

## 一、评测规模与样本定义 (40 次目标运行设计)

### 1. 对照组设置 (4 臂设计，共 32 目标运行 + 2 共享源任务)
为了在 40 次运行上限内获得最大统计效力，设置 4 个核心对比组，测试于 8 个经过严格定义的目标迁移任务实例：
- **评估组 B0**：无跨任务记忆多步 Agent（8 runs）；
- **评估组 B1**：原始失败轨迹检索（8 runs）；
- **评估组 B2**：动态结构化事实记忆（8 runs，核心强基准）；
- **候选组 M**：条件化失败约束记忆（8 runs）。
- **共享源任务 (Shared Source Episodes)**：2 个初始诱发任务（仅运行 1 次生成共享经历日志，供 B1, B2, M 共同使用）。
- **总评测模型运行数**：$$4 \text{ 组} \times 8 \text{ 目标任务} + 2 \text{ 源任务} = \mathbf{34 \text{ 次运行}} \le 40$$

### 2. 样本单位与任务设计 (Sample Unit Definition)
- **样本统计单位**：单一完整任务 Episode（定义为：`Task_ID` + 固定随机种子 `Seed` + 初始环境配置指纹 `Context_Fingerprint`）。
- **任务族与状态变更设计 (涵盖 4 类状态跳变)**：
  1. **任务 1~2 (State A: 持续阻碍)**：继承源任务阻碍（如端口 18080 仍被占用、文件仍为 0644），检验各组是否能够避免重复调用致命动作；
  2. **任务 3~4 (State B: 阻碍显式解除)**：环境在任务开始前已修复阻碍（端口已释放、文件已改为 0666），检验是否能主动撤销约束并恢复正常路径，**重点测算错误阻断率（False Block Rate）**；
  3. **任务 5~6 (State C: 无关属性变更)**：占用端口的进程名称/PID 改变，或文件修改时间改变，但核心阻碍依旧存在，检验规则是否抗无关干扰；
  4. **任务 7~8 (State D: 观测过期/不完整)**：环境存在隐式变更可能，检验是否能正确输出 `UNKNOWN` 并驱动主动探针，而非冒进或死锁。

## 二、四级决策归因体系 (Four-Tier Decision Taxonomy)

在小样本探索性实验中，绝不能将所有不理想结果一概粗暴断言为“理论被证伪”，必须按以下四级层级进行客观决策：

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 实现失败 (Implementation Failure)                                   │
│    现象: 解析器报错、执行器死循环、Token 溢出崩溃、环境脚本状态未重置    │
│    决策: 属于代码工程缺陷，定位并修复技术 Bug，严禁推论方法论好坏       │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 排查通过
┌───────────────────────────────────▼────────────────────────────────────┐
│ 2. 证据不足 (Inconclusive / Insufficient Evidence)                     │
│    现象: 组间方差极大，95% 置信区间重叠超过 80%，偶发环境超时           │
│    决策: 样本量不足以支持显著性推断，如实记录不确定性，绝不扩大主张     │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 证据充分
        ┌───────────────────────────┴───────────────────────────┐
        ▼                                                       ▼
┌──────────────────────────────────────┐ ┌──────────────────────────────┐
│ 3. 无独立收益 (No Independent Benefit)│ │ 4. 有初步收益 (Preliminary)  │
│    现象: M 相比 B2 无显著成功率/调用  │ │    现象: M 显著降低重复错误，│
│          优势，或错误阻断率显著上升    │ │          错误阻断率低，成本 │
│    决策: 判定约束状态机为冗余包装，   │ │          优于 B2 与 B0      │
│          彻底停止该方向扩张，归档结项 │ │    决策: 规划大规模独立验证 │
└──────────────────────────────────────┘ └──────────────────────────────┘
```

### 1. 杜绝伪统计学证伪规则
- **科学事实**：在 $N=8$ 的小样本下，双尾检验的统计功效（Statistical Power）先天有限。如果结果显示 $p > 0.05$，在统计学上仅代表**“在当前样本量下未能拒绝原假设”**，绝对**不等于“彻底证伪了该理论机制”**。
- **规范要求**：不得将“未达到统计显著”偷换为“证伪了核心科学问题”。若差异微弱，严格定性为“证据不足”或“在当前样本下未展现独立优势”。

### 2. 工程准出标准与科学结论的边界
- 原方案中设定的具体指标（例如“错误率降低 $\ge 20\%$”、“主动撤销率 $\ge 80\%$”、“虚假约束 $\le 15\%$”）：
  - **定性界定**：仅作为研发团队内部事先约定的**工程决策止损线（Engineering Go/No-Go Criteria）**，用于防范工程资源的无限度消耗；
  - **严禁越界**：绝不能将这些人为设定的工程准出百分比包装为学术上的“普遍科学规律”或“理论证伪分界线”。

## 三、硬件运行时间与资源预算客观测算 (RTX 2080 Ti 22GB)

为避免非严谨的时间承诺，将运行成本划分为**理论最坏预算**、**已知历史吞吐测算**与**未知不确定变量**三部分：

### 1. 理论最坏情况预算 (Theoretical Worst-Case Bound)
- 34 次完整运行 $\times$ 600 秒超时上限 = **20,400 秒 $\approx$ 5.67 小时**；
- 理论最大 LLM 调用：34 runs $\times$ 20 calls = 680 次 LLM Calls；
- 理论最大 Token 上限：680 calls $\times$ 3,000 tokens $\approx$ 2.04M Tokens。

### 2. 基于历史实测吞吐的基线预估 (Empirical Throughput Estimation)
- 在单卡 RTX 2080 Ti (22GB, AWQ 量化) 上，Qwen3-14B-AWQ 的实际生成吞吐约为 24~28 tokens/s，Prompt 处理约为 300~500 tokens/s；
- 历史实测中，一个 8~10 步的典型交互任务平均消耗单卡纯推理时间约 45~70 秒；
- 34 次运行的纯模型前向计算时间预估：
  $$34 \text{ runs} \times 60 \text{ s} \approx 2,040 \text{ s} \approx \mathbf{0.57 \text{ 小时 (约 35 分钟)}}$$

### 3. 未知变量与系统开销 (Uncertainty Factors)
- **容器与文件系统 I/O**：每次任务重置目录、权限刷新及进程启停（每次预计 0.5~1.5s）；
- **网络 Socket 探测重试**：等待端口释放或连接超时重试（预计累积 2~5 分钟）；
- **重规划分支排队**：发生拦截时偶发性生成长序列（单次约 10~15s）。
- **总耗时综合区间**：预计实际离线运行工时在 **1.0 ~ 2.5 小时之间**。严格禁止向管理层承诺未经端到端测量的固定工时。
