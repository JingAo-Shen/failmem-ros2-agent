# Phase P1d: Generic Interface Control (通用接口对照) 实验执行与分析报告

## 一、阶段定位与研究问题

- **阶段名称**：`P1d_GENERIC_INTERFACE_CONTROL`
- **核心研究问题**：在提供明确、通用的工具动作语义说明（$G$）后，现有的具体恢复经验（$C$）是否仍能带来额外的边际收益（即 $GC$ 对比 $G$）？
- **实验范围**：ScienceWorld `boil` 任务（Variation 0 与 Variation 2），共 16 个 episode（Block 5 与 Block 6，随机种子 3409）。
- **预算控制**：严格沿用累计 $10.00 美元预算池，本阶段上限 1000 次新增模型请求。

  - `getMoveableLiquids()` 判定源容器是否含液体，不含液体返回空或 `"does not contain any liquids"`。通用语义说明 $G$ 100% 符合模拟器物理逻辑。

### 1. 总体表现统计（各条件 4 个 Episode）

### 2. 主比较：GC vs G（在通用接口语义上，具体经验是否有额外收益？）

- **配对胜负平统计（共 4 对）**：
  - **任务成功率对比**：GC 胜 1 对（Var 2 Block 6: GC=100 vs G=75），G 胜 1 对（Var 2 Block 5: G=100 vs GC=72），平 2 对（Var 0 Block 5 & 6 均成功）。总体成功率持平（75.0% vs 75.0%）。
  - **最终得分对比**：GC 胜 1 对，G 胜 1 对，平 2 对。
- **双成功配对步数效率对比（2 对，均为 Var 0）**：
  - Var 0 Block 5 (M05 vs M02)：GC 决策步 18 步 vs G 决策步 22 步（$\Delta = -4$ 步，环境步 $\Delta = -4$）
  - Var 0 Block 6 (M15 vs M14)：GC 决策步 18 步 vs G 决策步 22 步（$\Delta = -4$ 步，环境步 $\Delta = -1$）
  - **双成功对平均决策步增量**：**-4.00 步**（GC 比 G 快 4 步达成目标）。
- **液体交互错误与探索抑制**：
  - 条件 G 产生了 2 次无效 dunk 错误（未关闭水槽排水孔即 dunk，以及对无水的浴缸 dunk）；
  - 条件 GC 产生了 0 次无效 dunk 错误。经验 C 中具体的“在水槽接水并转移”序列抑制了 G 条件下的盲目尝试。
- **Token 消耗与成本效率**：
  - GC 的平均执行耗时（42.0s）显著低于 G（67.8s）；
  - GC 阶段消耗 18,717 输出 tokens（$0.0625），而 G 消耗 29,840 输出 tokens（$0.1066）。说明经验 C 减少了冗余的内部推理发散。

### 3. 次要比较：G vs A, C vs A, GC vs C

- **G vs A (接口语义的独立价值)**：
  - 成功率提升至 75.0% 对比 50.0%；
  - 4 个配对中，G 胜 1 对成功率，得分 2 胜 0 负 2 平。说明清晰的通用动作接口语义即使没有具体成功/失败案例，本身就能显著提升 LLM 规划器的有效性。
- **C vs A (单一经验的迁移风险)**：
  - 成功率持平（50.0% vs 50.0%），但 C 表现出双刃剑特性：在成功的变体中步数大幅精简（Var 2 Block 5: 10 步 vs 24 步），但在未适应的变体中可能陷入局部死锁甚至惩罚（M01 触发 fatal penalty 导致 -100 分）。
- **GC vs C (组合的鲁棒性)**：
  - 成功率从 50.0% 提升到 75.0%（GC 胜 2 对，C 胜 1 对，平 1 对）。
  - G 提供的通用规则防止了 C 在某些极端情况下的逻辑崩塌（避免了 -100 的严重惩罚）。

### 4. 菜单交互与协议统计

- 16 个 episode 中共触发 16 次菜单消歧交互（A: 2, G: 5, C: 5, GC: 4）。
- `menu_blank_cancellations_count = 0`，全部消歧请求均由规划器输出合法数字序号完成消歧，未出现任何因空动作或无效格式导致的异常退出。
