# 强基线对照与单一可检验假设规范 (Strongest Baseline Specification)

> **科研准入与公平对比声明**：
> 1. 本规范坚决杜绝“为了凸显候选方案而故意弱化基线（设立稻草人基线）”的不端行为；
> 2. 对照核心 **B2 (动态结构化事实记忆)** 必须具备**同源证据、动态状态更新、适用条件检查、过期观测处理和在线重规划能力**，绝不预设为永不更新的静态规则库；
> 3. 不预设“负向记忆一定优于正向记忆”；任务成功率、错误阻断率（False Block Rate）与全生命周期成本必须三位一体联合衡量。

---

## 一、唯一下一阶段核心可检验科学假设

为了杜绝发散与多目标混杂，下一阶段（若开展实验）**仅且仅允许检验以下单一核心科学假设**：

> **核心假设 (Primary Testable Hypothesis)**：
> **“在具备相同环境交互证据与动态状态更新能力的前提下，引入显式条件化失败约束记忆机制（M），能否在不显著增加错误阻断率（False Block Rate）的同时，统计显著减少跨任务长程工具链中的重复工具失败；并且在全生命周期计费（含冷启动提炼与探针维护）下，取得优于动态事实记忆（B2）与经验回放（B3）的综合效用？”**

### 联合评估指标体系 (Three-Pillar Joint Evaluation)
1. **可靠性效力 (Reliability & Safety)**：
   - 任务最终成功率 (Task Success Rate, %);
   - 跨任务重复工具错误次数 (Repeated Tool Violations / Fatal Errors);
   - **错误阻断计数 (False Block Count)**：由于过时或错误约束导致智能体未能执行本可行、安全动作的次数。
2. **知识经济性 (Lifecycle Cost & Efficiency)**：
   - 全生命周期总 LLM 调用次数 (Total LLM Calls, 包含冷启动提取 + 运行时决策);
   - 全生命周期总 Token 消耗 (Prompt & Generated Tokens);
   - 跨任务摊销单任务调用开销 (Amortized Cost per Task over $N$ episodes).
3. **环境自适应性 (Adaptability to Invalidation)**：
   - 环境跳变时旧约束的主动撤销成功率 (Active Invalidation Success Rate, %).

## 二、五大实验对比组规范 (5-Arm Baseline Suite)

所有对比组必须运行在**完全一致的底层环境、公共局部执行器（CommonLocalPlanExecutor）、相同工具权限和预算上限**之下。

```
┌────────────────────────────────────────────────────────────────────────┐
│ 公共执行基座: 统一分块游标、重复拦截截断 (3-strike)、统一超时与工具集   │
└──────┬──────────────┬──────────────┬──────────────┬────────────────────┘
       │              │              │              │
┌──────▼─────┐ ┌──────▼─────┐ ┌──────▼─────┐ ┌──────▼─────┐ ┌───────────▼───────────┐
│ B0: 无记忆 │ │ B1: 原始失败│ │ B2: 动态事实│ │ B3: 成功片段│ │ M: 候选条件化失败约束记忆   │
│ 多步 Agent │ │ 轨迹检索    │ │ 记忆 (强对照)│ │ 回放        │ │ (解耦有效性与适用性门禁)   │
└────────────┘ └────────────┘ └────────────┘ └────────────┘ └─────────────────────────┘
```

### 1. 组 B0: 无跨任务记忆的多步 Agent (No-Memory Baseline)
- **机制原理**：标准的 ReAct / 多步局部规划智能体，跨任务环境状态与历史完全清空，任务间独立冷启动。
- **信息权限**：仅拥有系统提示词、基础工具集描述、以及当前任务环境在当前步骤的即时观测。
- **定位与作用**：测定通用大模型在当前任务族上的纯自主试错基准成本与固有失败率。

---

### 2. 组 B1: 原始失败交互证据检索 (Raw Failure Trajectory Retrieval / Reflexion-style)
- **机制原理**：在源任务中记录智能体遭遇失败的完整或局部文本交互片段（Command, Stderr, 局部报错上下文）。在新任务中，利用向量嵌入或 BM25 检索语义相似的前 $K$ 条原始失败片段，以自然语言反思附注的形式拼接在 Prompt 中。
- **更新与淘汰**：滑动窗口管理或语义相似度排序，不具备形式化状态机或因果谓词解析。
- **定位与作用**：检验未经结构化解析与状态门控的自然语言历史日志直接提示，是否存在注意力分散、Token 浪费或诱发幻觉。

---

### 3. 组 B2: 动态结构化事实记忆 (Dynamic Structured Fact Memory) —— 【核心强对抗基准】
> ⚠️ **严正声明**：B2 绝非静态不可变规则库！B2 与候选方案 M 共享**同等因果证据来源、相同的状态感知工具权限**。
- **机制原理**：
  - 维护一个**动态环境因果事实库**（World Fact Knowledge Base），事实以结构化命题存储（例如 `Fact: {resource: "port:8080", state: "occupied", holder: "pid:1234", verified_time: t}`）；
  - **动态状态更新**：允许智能体通过探针命令或动作反馈增删改事实条目；
  - **适用条件与过期检查**：每个事实带有生存时间戳（TTL），过期未验证事实自动置为 `UNCONFIRMED`；
  - **决策通道**：在重规划或多步规划时，将当前高置信度的活跃环境事实注入规划上下文，由 LLM 根据世界事实自主推理推导出哪些动作不应执行。
- **与 M 的本质区别**：
  - B2 是**世界状态事实（World State Facts）**，决策依赖 LLM 在线理解事实并自发规划规避；
  - M 是**动作级因果约束与显式生命周期门禁（Action-Level Constraint Gate）**，直接在执行前进行签名与谓词拦截。
- **关键检验点**：显式的动作约束门禁是否真的优于“给模型提供准确动态世界事实”？如果两者在成功率和成本上无差异，则 M 的约束状态机属于过度包装。

---

### 4. 组 B3: 成功片段回放 (Successful Sub-trajectory Replay / ExpeL-Replay style)
- **机制原理**：从源任务的成功执行轨迹中，提取出经过后置条件验证的多步有效动作切片（Sub-goal Action Chunks）。在迁移任务中，当检测到相似子目标时，优先通过分块游标调度器复用已验证动作。
- **定位与作用**：检验正向动作回放策略在面临环境扰动时的表现，与负向约束规避形成对称对照。

---

### 5. 组 M: 候选条件化失败约束记忆 (Candidate Conditional Failure Constraint Memory)
- **机制原理**：
  - 严格落实 `constraint_semantics.md` 中规范的三层解耦（Rule Validity vs Current Applicability vs Action Outcome）；
  - 维护生命周期状态机：`CANDIDATE`, `SUPPORTED`, `CONTRADICTED`, `RETIRED`；
  - 决策通道执行**本地确定性门禁拦截**（当且仅当适用性为 `APPLICABLE` 时驳回并精准注入受阻信息；当适用性为 `UNKNOWN` 时驱动探针刷新）。

## 三、公平对比、权限对称与全生命周期记账协议

为保证科研结论的绝对公正，所有评测组必须遵守以下记账与执行协议：

### 1. 执行器与工具权限绝对统一
- 所有组统一使用相同的工具集（POSIX shell / Docker API）；
- 若候选组 M 在判定适用性时需要执行探针命令（如 `lsof -i :8080` 或 `stat /file`），**探针调用严格计入该组的 Tool Calls 与耗时**；
- **探针权限对称共享**：其他组（尤其是 B2）完全具备调用相同探针命令的能力与权限，绝不对候选组开放特权探针后门。

### 2. 全生命周期记账矩阵 (Full Lifecycle Accounting Ledger)

```
总科研开销 = 共享公共经历获取成本 (Shared Source Cost)
           + 方法专属提炼/索引开销 (Method Extraction Cost)
           + 目标任务执行总开销 (Target Execution Cost)
```

| 成本组成项 | 计量单位 | 计入规则与公平性保证 |
| :--- | :---: | :--- |
| **共享来源经历获取成本** | LLM Calls, Tokens, Tool Calls | 在相同的源任务中运行并遭遇失败/成功的公共基础开销。**5 个组只发生 1 次公共采集，平摊共享记入账本**，杜绝各组重复生成。 |
| **方法专属提炼开销** | LLM Calls, Prompt/Gen Tokens | 各组从原始日志中提炼知识的额外计算：<br>- B0: 0（无提炼）<br>- B1: 向量嵌入计算或 BM25 索引构建<br>- B2: LLM 提取环境事实条目的调用与 Token<br>- B3: 成功轨迹切片与前置校验提取<br>- M: 约束三元组解析与前置谓词绑定开销 |
| **运行时探针开销** | Tool Calls, Execution Time | 执行前探针命令消耗的工具步数与实际时间，直接累加至任务执行计数中。 |
| **运行时决策开销** | LLM Calls, Prompt/Gen Tokens | 目标任务中生成规划、拦截反馈、重规划所消耗的调用与 Token。 |

### 3. 双轨成本汇报规范 (Dual-Track Cost Reporting)
在最终汇报中，必须同时展示：
1. **单任务纯测试开销 (Test-Time Only Cost)**：便于与传统只汇报单次测试的文献进行横向对齐；
2. **全生命周期摊销总成本 (Amortized Lifecycle Cost)**：
   $$\text{Amortized Cost}(N) = \frac{\text{Extraction Cost}}{N} + \text{Mean Execution Cost}$$
   其中 $N$ 为跨任务迁移的测试任务总数。必须绘制成本随任务数 $N$ 增长的摊销曲线，明确揭示拐点。

## 四、主要假设判别与否定边界 (Hypothesis Acceptance & Rejection)

实验结果对主要假设的判定逻辑如下表所示：

| 实验观测表象 | 对主要假设的判定 | 学术结论与后续决策 |
| :--- | :---: | :--- |
| M 相比 B2 显著降低了重复失败，且错误阻断率 $\le$ B2，且摊销成本更优 | **假设成立** (Hypothesis Supported) | 证实独立约束门禁相比纯环境事实具有确定性执行优势，可规划下一阶段论文写作。 |
| M 相比 B2 在重复失败和成功率上**无统计显著差异**，但 M 引入了额外的状态维护复杂度 | **假设被证伪** (Hypothesis Falsified) | **直接否定候选方案！** 证明约束状态机只是事实记忆（B2）的冗余包装，直接推荐使用更简洁通用的事实记忆。 |
| M 降低了重复失败，但**错误阻断率（False Block Rate）显著高于 B2**（发生守旧死锁） | **假设被证伪** (Hypothesis Falsified) | **直接否定候选方案！** 证明负向约束在复杂环境中容易反噬智能体探索能力，机制存在本质缺陷。 |
| M 的全生命周期成本在 $N=20$ 时依然**严重高于 B0（无记忆多步）** | **工程不经济** (Economically Inviable) | 否定该方法在边缘或轻量模型上的实用价值，终止扩展。 |
