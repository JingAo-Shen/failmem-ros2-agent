## 一、核心决策五问：现有收敛判定与研究取舍

### 问题 1：现有工作如何收敛？是具备工程闭环但研究结论有限的消极结果，还是已有新方法论证明？

**明确判定**：
现有工作属于**“具备可靠工程闭环执行体系，但在核心方法论上以消极结果（Bounded Negative Results）为主收敛的阶段性研究”**。

1. **工程闭环成果确立**：
   - 建立了包含分块游标队列（Chunk Cursor Queue）、严格状态差异检测（State Diff Hash）、三阶重复动作拦截（3-strike Loop Breaker）、执行器与 LLM 预算硬阻断的稳健运行框架（`CommonLocalPlanExecutor`）；
   - 建立了严格到每一次调用的审计凭据链（`llm_call_records` 与 Prompt/Generated Token 逐项累加断言），具备极高的科研复核确定性。
2. **核心科学假设未获支持（消极结论收敛）**：
   - **程序性记忆门禁（D-gated）未确立独立优势**：在 96 次受控评测中，D-gated 相比朴素动作回放（Replay）在成功率上完全持平（16/24），且因冗余状态判定导致 LLM 调用数与 Token 成本更高；
   - **高成功率依赖人工流程注入**：Stage 10 的 8/8 成功率已被证实源于公共工具说明与修复提示词中硬编码的人工 SOP 维修链；
   - **无流程提示下约束修复未带来收益**：Stage 11 的 32 次名义 2×2 比较证实，在去除人工 SOP 后，FocusedRepair 未提高成功率（7/8 vs 7/8），反而使 LLM 调用从 94 次增加至 107 次；且提示词存在事实与协议的非对称注入混杂，无法构成严格因果归因；
   - **任务集已退化为开发集**：现有 8 个 Workstation 任务经过多次工程适配与报错调试，已丧失作为学术泛化测试集的客观效力。
3. **收敛决策**：
   - 坚决杜绝将工程修复包装为“大模型自主记忆涌现”；
   - 如实以“工程有效、方法收益有限”的消极结果封存现有路线，不在旧环境旧方法上继续空耗 GPU 算力。

### 问题 2：若继续推进，下一阶段只回答一个什么可证伪的核心科学问题？

**唯一核心科学问题**：
> **“自主智能体（Agent）能否仅从真实交互失败中提炼出带有明确适用环境指纹的负向约束记忆（Constraint Memory），在跨任务长程工具链中统计显著地降低重复失败率，且在环境前提改变时能够主动撤销过时约束，从而在全生命周期计费下取得超越无记忆规划、轨迹回放与静态事实记忆的综合净收益？”**

**严格限定范畴**：
- **仅记录失败约束**：仅提炼“在何种前置观测条件下，何种动作不可行，其判定证据为何”；
- **坚决不记录成功动作链**：严禁保存成功的完整 SOP 动作序列，彻底杜绝退化为脆弱、过拟合且依赖人工流程注入的动作回放。

### 问题 3：该方向相比现有方案增加了什么具体的可检验假设？

| 现有方案体系 | 核心机制与主要缺陷 | 候选方向新增加的具体可检验假设 [待文献核验] |
| :--- | :--- | :--- |
| **基于成功的经验/轨迹回放**<br>(Trajectory Replay / ExpeL) | 记录成功动作链并在相似场景中粗暴复现。缺陷：环境扰动极易引发执行中断；若环境存在隐式依赖变化，容易盲目重放造成破坏。 | **假设 1（负向剪枝优于正向引导）**：在长程复杂工具链中，通过负向约束剪掉已知致命死路，其跨任务迁移鲁棒性显著高于正向动作模仿。 |
| **通用自省与反思**<br>(Reflexion / Self-Refine) | 提示 LLM 生成非结构化自然语言反思（如“下次要注意先检查状态”）。缺陷：语义模糊、缺乏确定性门禁、易随上下文变长发生注意漂移。 | **假设 2（观测指纹绑定假设）**：将失败条件严格量化为结构化的环境状态指纹（Observation Fingerprint），能够通过轻量确定性门禁精确阻断同类失败，无需在 Prompt 中堆叠冗长反思日志。 |
| **静态规则与提示注入**<br>(Static SOP / Recipe Injection) | 人工在 System Prompt 中硬编码操作守则。缺陷：抹杀智能体自适应能力；规则一旦过时将导致系统死锁；跨任务维护成本极高。 | **假设 3（主动撤销与版本失效假设）**：当后续探针观测到原约束成立的前提条件不复存在时，智能体能够主动将约束失效化并恢复对原动作的探索，消除静态规则带来的“守旧死锁”。 |
| **全生命周期核算**<br>(Lifecycle Cost Accounting) | 现有多数工作忽视生成记忆本身的试错成本，仅汇报检索后的单次测试表现。 | **假设 4（全生命周期净收益假设）**：在计入提炼约束所耗费的初始试错成本后，在连续多任务转移中，该机制的累计 Token 与工具调用成本仍显著低于基线。 |

### 问题 4：如果继续，什么样的实验结果将直接证伪/否定该方案？（硬性止损线）

若开展实验，一旦出现以下**任一硬性止损指标**，立即判定本候选假设被严格证伪，彻底终止本课题方向，不作任何借口性参数调试：

1. **迁移阻断失效线（No Transfer Benefit）**：
   - 在迁移到具备同类底层约束的新任务集时，候选约束记忆组相比“无记忆多步基线”的重复工具错误率降低幅度 $< 20\%$，或者任务成功率未展现出统计显著的优势。
2. **守旧性死锁线（Invalidation Failure）**：
   - 当测试环境显式解除了阻碍条件（例如环境依赖修复、锁文件主动清理、版本升级）后，智能体主动撤销过时约束并恢复目标动作尝试的比例 $< 80\%$；若因记忆残留导致的假性阻塞率高于无记忆基线，直接判定机制失败。
3. **全生命周期成本倒挂线（Lifecycle Inefficiency）**：
   - “形成约束消耗 + 维护检验消耗 + 注入推理消耗”的总成本，超过了其避免试错所节省的成本；在连续 8 个迁移任务的总开销大于无记忆基线。
4. **归纳幻觉超标线（Over-generalization Rate）**：
   - 从临时网络抖动、偶发超时等非确定性故障中错误归纳出“虚假永久约束”的比例 $> 15\%$，破坏了正常操作空间。

### 问题 5：综合当前证据，给出明确取舍建议：是就此结项，还是开展下一阶段概念验证？

**明确决策建议**：
建议**“以极其严苛的单阶段准入准出标准，开展最小规模概念验证（Minimal Proof-of-Concept, PoC）；若首阶段未突破上述止损线，坚决彻底结项”**。

**论证理由**：
1. **为什么不直接彻底放弃？**
   - FailMem 前期在“状态差分拦截”、“确定性门禁”和“单步结构化因果事实”上的工程代码已完全跑通；
   - 否定 D-gated 正向程序记忆，并不代表“经验约束”没有价值。在计算机体系结构与编译优化中，“分支负向缓存”历来比“完整路径预测”更轻量、更易维护。该候选方向逻辑自洽，且具备清晰的可证伪设计。
2. **为什么必须受控于最小概念验证？**
   - 避免重蹈“为了发表论文而不断给模型加提示补丁”的覆辙；
   - 必须抛弃已过拟合的 Workstation 玩具环境，直接进入真实容器化测试环境；
   - 设定单卡算力硬上限与一票否决权，确保科研投入产出比绝对可控。

### 1. 约束记忆形成机制 (Extraction & Evidence Formation) [待文献核验]
- **触发时机**：当工具执行返回明确的否定状态（如权限被拒、依赖版本不满足、端口冲突、文件锁互锁），且该失败导致执行停滞或被重复拦截命中。
- **提取要素**：严格由结构化解析器从实际执行跟踪中提取：
  1. `action_signature`: 动作名称与核心参数模式（如 `apt-get install pkg_a` 或 `systemctl start service_b`）；
  2. `precondition_fingerprint`: 失败发生时确定性的环境上下文特征（如 `kernel_version`, `installed_lib_version`, `lock_file_present`, `port_bound`）；
  3. `failure_evidence`: 导致该约束生成的原始错误日志摘要或退出码；
  4. `abstention_flag`: 判定是否具备足够因果确定性。
- **严格禁忌**：严禁保存“随后成功的修复动作序列”。智能体不记忆“怎么做是对的”，只记忆“何种条件下该路径被阻断”。

### 2. 条件绑定与版本控制 (Condition Binding & Versioning) [待文献核验]
- 约束必须与具体的环境指纹版本强绑定：
  ```json
  {
    "constraint_id": "c_20261010_01",
    "target_action": "bind_port(8080)",
    "context_fingerprint": {
      "process_listening_port_8080": true,
      "process_name": "nginx"
    },
    "failure_evidence": "EADDRINUSE: address already in use 0.0.0.0:8080",
    "lifecycle_status": "ACTIVE",
    "genesis_cost": {
      "trial_steps": 3,
      "llm_prompt_tokens": 4210,
      "llm_generated_tokens": 185
    }
  }
  ```
- 约束不具备全知全局效力；一旦 `context_fingerprint` 在后续观测中失配，该约束自动丧失阻断效力。

### 3. 主动撤销触发机制 (Active Invalidation Trigger) [待文献核验]
- **触发逻辑**：智能体在后续规划中执行了环境探针（如 `lsof -i :8080` 或 `dpkg -l`），返回的最新观测表明原 `context_fingerprint` 中的核心谓词已被颠覆（例如 `process_listening_port_8080: false`）。
- **状态转移**：
  1. 约束状态由 `ACTIVE` 转移为 `PROBATION`（试探期）；
  2. 决策门禁释放对该动作的阻断，允许规划器在当前步骤重新调度该动作；
  3. 若该动作在新环境下执行成功，该约束状态彻底更新为 `REVOKED` 并归档；
  4. 若该动作依然失败，则更新指纹特征并维持 `ACTIVE`。

### 4. 影响决策通道 (Decision Pathway Injection) [待文献核验]
- **严禁全量上下文拼接**：严禁将历史所有失败记录作为自然语言长文本拼接入 System Prompt。
- **通道分流**：
  - **动作候选门禁**：在本地执行层或轻量规划前置拦截。若 LLM 提议执行的动作命中当前活跃约束，本地执行器直接将其驳回，并向 LLM 反馈受限原因；
  - **精准聚焦注入**：仅在重规划或拦截提示中，注入当前与该动作直接相关的单一约束条目（包含其前置指纹与证据），引导规划器选择旁路或先解除前置条件。

### 5. 拒识与不采用标准 (Abstention & Rejection Criteria)
- **拒识条件**：
  - 遇到未知随机错误码（如网络超时、SIGKILL、不可重现的并发竞争）；
  - 环境特征无法被现有观测工具精确采样；
  - 判定置信度低（单一单次偶发失败）。
- **处理**：此类失败仅作为常规单步报错反馈给规划器，**坚决不固化为持久约束条目**，防止形成“错误偏见记忆”。

### 6. 来源尝试计入与全生命周期核算 (Source Trial Accounting)
- **科研记账原则**：
  - 任何一条生效约束，其诞生过程消耗的所有 Tool 调用、LLM 调用、耗时与 Token，全部记录在 `genesis_cost` 中；
  - 在跨任务评测汇报时，**总成本 = 产生约束的冷启动成本 + 后续各任务执行成本**；
  - 杜绝“将训练/探索阶段的成本剥离，只汇报干净测试表现”的伪高效宣称。

## 三、真实评测场景与强基线设计 (Evaluation Domain & Baselines)

### 1. 真实评测场景：本地容器化软件构建与服务恢复环境
- **抛弃玩具模拟器**：彻底弃用以字典状态维护的 Workstation 玩具环境；
- **环境载体**：轻量 Docker 容器（标准 Ubuntu 22.04 LTS 环境），具备真实的文件系统、进程命名空间与网络栈；
- **任务族类别（4 类真实运维与编译任务，共 16 个具体实例）**：
  1. **依赖互锁与编译失败（Dependency & Build Locks）**：例如多版本 Python/C++ 共享库冲突、`apt` 锁未释放；
  2. **端口占用与死锁服务（Service Binding & Port Contention）**：例如僵尸进程占死端口、守护进程未退出；
  3. **权限与路径隔离（Permission & File Isolation）**：配置权限缺失、只读挂载与符号链接断裂；
  4. **环境跃迁与旧约束失效（Environment Mutation & Invalidation Testing）**：前置任务植入故障，后置任务在升级修复包后测试智能体是否能主动打破旧约束完成操作。
- **客观验证特性**：
  - **可重置性**：容器镜像秒级销毁重建；
  - **客观可断言**：通过 `curl` 响应码、二进制产物校验和、服务退出码进行独立评分；
  - **报错不泄题**：原生 bash / compiler 的 stderr 报错，绝不包含任何人工硬编码的“如何修复”提示。

### 2. 五大强基线对比矩阵 (Strict Baseline Suite)

| 实验基线组 | 记忆与先验机制 | 决策与执行逻辑 | 预期检验点 |
| :--- | :--- | :--- | :--- |
| **B1: No-Memory Baseline**<br>(无记忆多步规划) | 零跨任务记忆。每任务独立启动。 | 标准 ReAct / 多步局部规划 + 错误反馈试错。 | 测定通用大模型在纯自主状态下的基准成功率与真实试错成本。 |
| **B2: Raw Trajectory Retrieval**<br>(原始轨迹语义检索 / Reflexion 范式) | 存储完整的历史失败交互记录，基于语义相似度检索前 $K$ 条日志。 | 将检索到的失败日志全文拼接至 Prompt 作为参考。 | 检验长上下文反思是否存在注意漂移、幻觉与冗余 Token 开销。 |
| **B3: Static Fact Memory**<br>(同等事实结构静态因果库) | 包含与约束同等信息量的静态环境因果断言，但无生命周期与撤销逻辑。 | 作为静态环境规则始终注入提示词。 | 检验静态规则在环境前提改变时是否引发“守旧死锁”。 |
| **B4: Trajectory Replay**<br>(历史成功轨迹动作回放) | 记录成功任务的动作序列切片。 | 匹配相似任务时优先回放历史成功动作。 | 检验动作回放策略在轻微扰动或故障干扰下的脆弱性。 |
| **B5: Candidate Method**<br>(带适用条件与主动撤销的约束记忆) [待文献核验] | 仅提炼结构化负向约束，绑定观测指纹，具备主动撤销与决策通道门禁。 | 局部约束门禁拦截 + 探针观测触发失效化。 | 核心检验：能否在更低 Token 下降低重复错误，且在环境修复时打破约束。 |
