## 1. 任务定义与边界
- **场景限定**: 单个 ROS2 移动机器人（基准形态：TurtleBot3 差速轮式底盘），室内仿真环境。
- **任务目标**: 给定初始目标语义与安全观察站位/区域，机器人自主导航至指定站位，执行传感器观察，确认目标物体的可见性与状态。
- **排除范围**: 暂不涉及机械臂抓取、多机器人协作、在线强化学习微调、端到端视觉大模型训练、Web 控制平台和实物真机部署。

## 2. 目标实体位置与机器人观察站位解耦及几何实例

必须严格区分**目标物体物理实体位姿**与**机器人应到达的安全观察站位（Observation Stance）**：
- **物理实体约束**: 目标物体具有实体碰撞包围盒（例如半径 $r_{\text{target}} = 0.25\text{m}$ 的储物箱或台面），机器人底盘具有物理碰撞半径（$r_{\text{robot}} = 0.20\text{m}$）。
- **禁止碰撞行驶**: **严禁机器人为满足距离阈值而直接驶入目标物体内部**。评测判定机器人的到达目标是“安全观察站位”。
- **成功判定要素的解耦与独立计算**:
  1. **到达误差 ($\epsilon_{\text{arrival}}$)**: 机器人底盘中心坐标 $P_{\text{robot}}$ 与目标安全观察站位 $P_{\text{stance}}$ 之间的平面欧氏距离 $\|P_{\text{robot}} - P_{\text{stance}}\| \le 0.30\text{m}$；
  2. **朝向对准误差 ($\Delta\theta$)**: 机器人前向朝向与从机器人指向目标物体的视线矢量夹角 $|\Delta\theta| \le 45^\circ$（目标处于传感器 $\pm 45^\circ$ 的水平视场内）；
  3. **物体可见距离 ($d_{\text{target}}$)**: 机器人传感器与目标物理实体中心距离 $d_{\text{target}} \in [0.5\text{m}, 2.5\text{m}]$；
  4. **视线遮挡 (LOS Occlusion)**: 从相机传感器原点向目标物体边界框投射射线，无其他墙体或障碍实体阻挡；
  5. **稳定时间 ($t_{\text{stable}}$)**: 机器人进入阈值区后线速度与角速度维持稳定（线速度 $<0.05\text{m/s}$，角速度 $<0.05\text{rad/s}$），持续时间 $\ge 2.0\text{s}$。

### 具体几何实例 (证明成功条件可同时满足且物理安全)
- **目标物体实体中心**: $P_{\text{target}} = (5.00, 3.00, 0.00)$，外接圆碰撞半径 $r_{\text{target}} = 0.25\text{m}$；
- **预设安全观察站位**: $P_{\text{stance}} = (4.00, 3.00, 0.00)$，朝向角 $\theta_{\text{stance}} = 0\text{ rad}$（沿 $+x$ 轴正对目标）；
- **机器人实际停稳位姿**: $P_{\text{robot}} = (3.90, 3.00, 0.00)$，朝向 $\theta_{\text{robot}} = 0\text{ rad}$：
  - *到达误差*: $\|(3.90, 3.00) - (4.00, 3.00)\| = 0.10\text{m} \le 0.30\text{m}$ (通过)；
  - *实体物理安全间隙*: 机器人底盘边缘与目标外壁距离为 $d_{\text{clearance}} = (5.00 - 3.90) - (0.20 + 0.25) = 1.10 - 0.45 = 0.65\text{m} > 0$（无物理碰撞风险）；
  - *物体可见距离*: 距离目标中心 $1.10\text{m} \in [0.5\text{m}, 2.5\text{m}]$ (通过)；
  - *朝向夹角*: 视线方向为 $(+1, 0)$，朝向夹角为 $0^\circ \le 45^\circ$ (通过)；
  - *射线遮挡*: 直线路径净空无障碍 (通过)；
  - *稳定时间*: 维持停稳 $2.2\text{s} \ge 2.0\text{s}$ (通过)。

## 3. 完整动作空间 Schema 与预算契约

机器人与环境交互的动作空间采用强类型 Schema。未实现的底层行为（如未封装的 Back-up）从本轮可用动作中完全移除：

| 动作名称 | 字段 Schema | 预算消耗与语义 | 说明 |
| :--- | :--- | :--- | :--- |
| `navigate` | `{"action": "navigate", "action_id": str, "params": {"goal": [x, y, yaw], "frame_id": "map", "timeout_sec": 60.0}}` | 消耗 1 次动作预算及物理实际耗时 | 底层对接 Nav2 `NavigateToPose` Action。带坐标系及动作级超时。 |
| `observe` | `{"action": "observe", "action_id": str, "params": {"target_id": str}}` | 消耗 1 次动作预算及传感器采集耗时 | 触发当前站位下的目标可见性检测。 |
| `inspect_status` | `{"action": "inspect_status", "action_id": str, "params": {}}` | 消耗 1 次动作预算（即时读取，<0.5s） | 读取当前里程计估算 `/odom`、激光雷达测距摘要与局部代价地图状态。 |
| `clear_costmap` | `{"action": "clear_costmap", "action_id": str, "params": {}}` | 消耗 1 次动作预算及服务耗时 (~2s) | 触发 Nav2 `clear_costmap_service`。**仅重置局部代价地图瞬态传感图层，绝不能消除物理世界中的实体障碍**。 |
| `retry` | `{"action": "retry", "action_id": str, "params": {"original_action_id": str, "replayed_params": dict}}` | 消耗 1 次动作预算 | 显式重放原 `action_id` 及其参数，并记录重试计数。同一上下文状态同动作最多重试 1 次。 |

- **统一预算上限 (待真实环境实测后校准冻结)**:
  - 任务最大高层动作数: $\le 20$ 步；
  - 恢复动作调用总上限: $\le 3$ 次；
  - 仿真物理时间预算: $\le 180\text{s}$；
  - Wall-clock 超时守护器: 300s 强制终止，防止推理死锁挂起。

## 4. 感知接口来源界定与真值隔离

### 4.1 `observe` 接口的信息来源界定
- **理想化可见性传感器 (Idealized Visibility Sensor)**:
  - 现阶段采用基于仿真真值的**理想化视锥遮挡传感器**，其内部实现为物理射线求交与几何计算；
  - **严格标记**: 必须在报告与代码中明确标记为“基于几何碰撞的理想化视锥传感器”，**严禁宣称真实视觉模型（VLM/Object Detection）识别已完成**；
  - **物理约束强制施加**: 限制水平视场 FOV $90^\circ$、有效视距 $[0.5\text{m}, 2.5\text{m}]$、视线遮挡物理检测、必须带有时效性时间戳；
  - **基线统一**: 所有对比方法（无记忆、反思基线、FailMem）调用完全相同的 `observe` 接口，保证信息获取公平。

### 4.2 公共 Verifier 与独立 Evaluator 隔离契约
- **隐藏事件只进入故障注入器与独立 Evaluator**:
  - 仿真内部的真实故障标记（Ground-Truth Fault Tag）和隐藏目标移动，仅供注入器（Injector）生成物理表现和独立评测器（Evaluator）打分判定；
  - **严禁任何隐藏故障事件直接触发 Agent 侧的记忆失效**。
- **Agent 侧失效依据的严格限定**:
  - Agent 侧的记忆更新或失效，**仅能且必须**依据公开观察结果（如 `observe` 返回 `NOT_VISIBLE`）、公开地图/代价地图变化（如接收到 `clear_costmap` 返回或静态地图广播更新）、预先定义的生存时间（TTL）或重新验证逻辑；
- **反例契约 (Negative Counterexample)**:
  - **反例场景**: 任务中途隐藏目标已被外部移动至新位置，但机器人尚未到达或尚未执行 `observe`，公开传感器与观察历史未发生任何改变；
  - **禁止行为**: 在此状态下，Agent 侧的记忆库状态、置信度或失效标志**严禁因隐藏事件而发生改变**。若记忆库在没有公开感知事件的情况下自动标记该位置失效，判定为真值泄漏作弊。
- **目标搜索合法性**:
  - 当目标经观察确认丢失后，Agent 自主规划搜索动作并在后续 `observe` 中重新捕捉到目标，属于合法探索，不计为作弊；
  - 判定是否泄漏，完全由底层数据通道与动作输入参数审计决定（检查参数是否在观测前凭空出现）。

## 5. 故障表现、持续性与解除规范 (非必然因果性修正)

纠正此前将故障与恢复写成“必然导致碰撞/必然恢复”的绝对化表述，明确物理概率与外生生命周期：

1. **实体障碍 (Physical Obstacle)**:
   - **外生生命周期**: 实体障碍的出现与移除由**预先冻结的外生调度计划（Exogenous Schedule）**决定，绝不因 Agent 调用了某个方法或声明“恢复成功”而自动消失；
   - **持续性与非必然性**: 障碍实体持续存在期间，阻挡对应物理通道。若机器人盲目发起沿原通道的轨迹重试，具有高碰撞或规划失败概率，但并不等同于“所有重试必物理碰撞”（机器人局部规划器可能因探测到障碍而主动刹停或报错拒绝执行）；
   - **清图无效性**: 对实体障碍执行 `clear_costmap`，仅清空传感器缓存；下一次传感器扫描周期（如 100ms）后，激光雷达将再次测得实体障碍，局部代价地图重新膨胀阻挡。
2. **瞬态虚假噪点 (Transient Sensor Artifact)**:
   - 激光雷达瞬时噪点在代价地图上残留虚假障碍；
   - 执行 `clear_costmap` 后噪点图层被清空，在无实体障碍且传感器无新增噪点的前提下，通道恢复畅通。
3. **目标移动 (Target Relocation)**:
   - 目标物体物理移动后，原观察点无法满足视线或距离可见条件；机器人需根据策略执行新观察站位规划。

## 6. 时钟管理与仿真暂停机制契约

- **时钟基准**:
  - 物理仿真与 Nav2 动作基于 ROS2 仿真时钟 `/clock` (`use_sim_time:=true`)；
  - 外部 Wall-clock 独立运行，作为系统卡死守护器。
- **仿真暂停 (Pause/Resume) 执行边界**:
  - **仅允许在明确的高层决策边界执行暂停**: 当上一个高层动作已彻底结束（Action 达到终态 `SUCCEEDED`/`ABORTED`/`CANCELED`），且 Agent 进入纯文本/大模型耗时规划时，方可暂停物理仿真；
  - **严禁在动作执行中途随意暂停**: 严禁在未完成的 Nav2 Action 运行中、等待局部控制器回调或等待传感器扫描更新时暂停，避免破坏物理动力学与控制环路一致性；
  - **状态标记**: 若当前环境基础设施未打通 ROS2/Gazebo 的 pause/resume 服务，一律如实标注为 **`NOT_RUN`**，严禁以文档声明替代真实测试。
